Seed cover rejects short sequences

Why Nextclade rejects short EV-A71 fragments, and the options to fix it.

1. How the check works today

  • k-mer: a run of k bases (here 6)
  • Seed: a stretch where the query matches the dataset reference sequence, grown from an exact k-mer match
  • Seed cover: the share of the query inside seeds
  • Check: below minSeedCover (0.79 for EV-A71), Nextclade does not align the query
Seeds compare the query with the reference sequence, not with the tree

  1. 1. Find seeds

    Take a 6-mer every 25 positions, skipping the 3rd base of each codon. It must match the reference exactly.

    kmerLength 6kmerDistance 25seed_match.rs#L241-L274
  2. 2. Extend

    Grow the seed left and right. Stop when more than 15 of the last 30 bases differ, or when the query ends.

    windowSize 30allowedMismatches 15seed_match.rs#L116-L177
  3. 3. Trim the ends Flaw

    Cut each end back to the longest run of matches in its last 30 bases.

    Also done where the query simply ends. Costs up to 29 nt per end.

    seed_match.rs#L140-L157, #L179-L196
  4. 4. Cut into pieces Flaw

    Split the seed into 30 nt pieces. The last piece overlaps the one before it.

    Overlapping pieces do not count. An 89 nt seed counts as 60 nt.

    minMatchLength 30seed_match.rs#L201-L221
  5. 5. Chain

    Keep the best set of pieces that do not overlap.

    seed_match.rs#L326-L456
  6. 6. Check

    Cover = counted nt / query length. Reject the query if the cover is below minSeedCover.

    minSeedCover 0.79seed_match.rs#L484-L497

4. Solutions

The two flawed steps cause the bias, so the fix belongs in the seed code.

A. Fix the seed code

Nextclade changechanges alignment output
Where
fn SeedMatch2.extend_seed() in packages/nextclade/src/align/seed_match.rs
Change 1
count the whole seed: the last piece takes the rest (30 + 30 + 40 nt)
Change 2
trim only where extension stopped on mismatches. At the query end, drop only end mismatches
Status
not implemented. Effects below come from the simulator
  • +Length no longer matters: 100 nt at 13% divergence scores like 2,000 nt
  • +Only raises cover: no dataset rejects more sequences
  • =Alignments may shift slightly: seeds also guide the aligner. Needs a comparison with the current output on the test datasets
  • -Weaker type filter for short fragments unverified: divergent short fragments also gain (simulator, 100 nt with 30% subs: 48% to 78% cover). Long divergent sequences pass already today. Not measured with real CVA genomes
Mean cover, EV-A71 reference with random substitutions
Dots: Nextclade, 20 fragments. Lines: simulator, 60 fragments.

C. Filter types by private subs per 100 nt

dataset changeworks now, as QC flag
Private subs
substitutions that the nearest tree node does not have
QC rule
privateMutations in pathogen.json
Option
lengthScaling, since 3.30.0: limits scale with sequence length
  • +Separates types at every length: median EV-A71 0 to 3, CVA 11 to 29 per 100 nt
  • =Flags, does not reject: bad QC status, alignment kept
  • -Needs new limits: with the EV-A71 limits (typical 60, cutoff 175 per 7,408 nt), the score reaches 100 at about 3 subs per 100 nt
  • -Fails outside the capsid: in the 5'UTR and P2/P3 regions, 23 of 238 CVA fragments look like EV-A71 (capsid P1: 0 of 165). EV-A types share these regions by recombination
  • -Uneven rates: some regions mutate faster than the genome average, so one limit per 100 nt fits some regions worse
